Added

  • Mac: a machine switcher opens another machine's hub in the window. The sidebar's first row picks "This Mac" (the native pages) or another machine's hub, whose web app then fills the window in a web view. The hub signs it in as it does a browser on this Mac: the owner's own tailnet device needs no pairing, any other device gets the web app's pairing card. The view stays on that hub's origin (other links open in the default browser, file: never loads), keeps its own web data per hub, and a strip in the title bar names the machine. The list holds the hub this Mac's satellite agent reports to and hubs added by address in Settings › Integrations › Remote › Other hubs; the last pick is remembered (#681).

  • iPhone and web: a machine strip on the Sessions page. One chip per machine the hub lists, with an online dot, its name, "N working · M waiting" and, when it is offline, "last seen 2h". Tapping a chip shows only that machine's sessions; tapping it again shows all. The strip hides when the hub has one machine, and orders machines like the Mac's "Other machines" group (online first, then name). No new hub route (#1443).

  • iPhone, web and Mac: thinking cards say how long the model thought. A thinking card reads "Thought for 12s" or "Thought for 1m 5s" from the hub's duration_s, and plain "Thought" when the hub sent none. One formatting rule per client (ThoughtLabel.text on iOS and the Mac, Fmt.thought on the web) (#1440).

  • Remote approvals show and answer unnumbered menus too. A tmux-mode prompt whose options are an arrow-select list ("❭ Option A", the shape of Devin's ask-question panel) now reaches the approval card as its real labels, numbered top to bottom, instead of the generic Allow / Always / Deny guess. Answering a row walks the pane's cursor with arrow keys and confirms; numbered menus keep sending their own digit, and Devin's select widget now parses its selected row ("❭" is a different glyph than Claude's "❯"). Option labels join the request fingerprint, so a question that swaps its choices can't be answered by a stale tap.

  • Hub: thinking messages carry how long the model thought. kind: "thinking" messages from Claude Code, Codex and opencode now carry duration_s, so the clients can show "Thought for 12s". Claude Code and Codex time it from the record before the thinking record to the thinking record; opencode from its own reasoning time span. Other harnesses, and records with no usable timestamps, leave it out (#1440).

  • Mac: Settings › Remote can keep this Mac's agent running. On a Mac paired as a satellite of another machine's hub, a "Keep this Mac's agent running" switch installs or removes the agent's LaunchAgent through swe remote agent --install / --uninstall, and says whether it is running. The switch is hidden on the Mac that hosts the hub and on a Mac that was never paired (#1438).

  • swe remote agent --install keeps a satellite running. Like swe remote serve --install, it runs swe remote agent as a LaunchAgent on macOS (com.cwenlong.quiver.remote-agent) or a systemd user unit on Linux (quiver-remote-agent.service), separate from the hub's, so it starts at login or boot and restarts if it exits. It logs to ~/.quiver/data/remote/agent.log, turns on lingering or says how, and refuses on a machine whose own hub is installed (and the hub's install refuses next to an installed agent), since the two would share data/remote/cursors/. Only one agent runs per ~/.quiver: a second one exits at start, and --install refuses while a shell-started agent runs. --uninstall removes it and --status [--json] shows it. install-app.sh now restarts the agent on a new bundle as it does the hub (#1438).

  • swe init: the hub's MCP servers in extra accounts. A fourth switch, accounts.sync.mcp, off by default (swe config set accounts.sync.mcp true, or the new "MCP servers" switch on the Mac Accounts page's Shared content card). With it on, swe init merges every server in ~/.quiver/mcp.json, rendered as swe mcp sync quiver renders it, into each extra Claude account's .claude.json (the mcpServers member only) and each extra Codex account's config.toml ([mcp_servers.<name>] tables only). The login and every other key keep their bytes. A server the account already has under the same name is reported as a conflict and left alone, and a file that is not valid JSON or TOML is reported and never written. Writes go through a temp file and rename after a backup in ~/.quiver/backups. Each server swe writes is recorded in data/account-mcp.json, and switching off then running swe init removes only those, and only while the account has not edited them. Closes #888.

  • Hub: switch the model of an opencode session attached through opencode serve. The model control op on a serve session records a provider/model pick on the session's supervised row, and the next prompt_async carries it as {providerID, modelID}, so the switch applies from the next turn; a bare name is refused. opencode rows now list serve in model_modes, so the iPhone's Model menu shows on them with no app change. This closes model switching on every API channel (#643).

Security

  • Remote: revoking a lost phone works when it shares the owner's tailnet login. The owner's own tailnet devices get in without pairing, and Revoke refused their tailnet:<node> ids, so a lost phone signed in to the owner's Tailscale account walked straight back in through Safari. The hub now records those sign-ins (tailnet_signins.json), lists them in GET /v1/devices, web Settings ("Signed in through Tailscale") and swe remote devices, and POST /v1/devices/revoke / swe remote devices --revoke=tailnet:<node> revoke one: that node gets no owner identity, and devices paired from it are signed out, until a pair request from it is approved again. Revoking a device paired through a tailnet request revokes its node too. The owner's other devices keep working (#966).

  • Mac app: the fan helper is checked against Quiver's own signature before it runs as root. The one-time install copied Quiver.app/Contents/MacOS/QuiverFanHelper to /Library/PrivilegedHelperTools and only checked that the copy matched a hash taken before the password prompt. The bundle is user-writable, so anything running as the user could patch the helper beforehand and have it run as root once the user typed their password. A build signed by a team (Developer ID, or the Apple Development identity dev builds pick up) now has the root script verify the root-owned copy with codesign --verify --strict against identifier "QuiverFanHelper" and that team, and deletes it and stops otherwise. Ad-hoc builds have no signature to check against and keep the hash check alone. Installed helpers are not reinstalled, so nobody is asked for their password again (#967).

  • Mac app: the fan helper only takes requests from Quiver itself, checked by its code signature. The running root helper held the fans for any request whose owner was a live process named Quiver, so a program called /tmp/Quiver qualified. The install now pins the installing app's signature in the launchd job (--owner-team <team> --owner-identifier <id> for a team-signed build, since the team also signs the Python bundled for swe; --owner-cdhash <hash> for an ad-hoc one), and the helper checks each request's owner against it through its audit token and SecCodeCheckValidity, keeping the answer per process (pid and pid version) so a reused pid is checked afresh. A job without a valid pin starts nothing. The helper is now version 4 and writes its version into /var/run/com.cwenlong.quiver.fan.json. On launch, Quiver finds a helper older than that, says why it needs replacing, and offers "Update helper" (one administrator password prompt) or "Not now". Not now is remembered for this version: the old helper is left unused, the fans stay with macOS, and both fan popovers show the reason with an "Update fan helper" button; Set speed or the temperature rule's switch also updates it (#967).

  • Remote: a local process can no longer claim the owner's tailnet identity. Behind tailscale serve the hub read the client from X-Forwarded-For on every loopback connection, so any process on the hub machine, another user's included, could name the owner's phone and get owner powers (launch agents, approve pair requests, read API keys). It now believes the header only when the OS places the connection's far end in the Tailscale daemon: a root-owned socket in /proc/net/tcp on Linux, a root process or a binary in a root-owned /Applications/Tailscale.app per netstat -anv on macOS. Anyone else is read as a loopback client with no tailnet identity. The hub machine's own tailnet node also stops counting as the owner's device: serve's local listener forwards any local process as that node. The owner's phones and other computers get in as before, and paired devices are unaffected; a browser on the hub machine now pairs (#965).

  • The remote hub refuses wildcard and non-tailnet binds. swe remote serve --host=0.0.0.0 — or a LAN address, a link-local address, or a name that resolves to one — used to be taken verbatim; serve and serve --install now refuse it and name --unsafe-bind-any as the explicit override, matching the tailnet-only spec. Bind addresses may be loopback or a Tailscale address (100.64.0.0/10, fd7a:115c:a1e0::/48), by literal or by resolved name, and --install carries the flag into the service's command line when it was given.

  • GET /v1/status answers {ok, v} only. The unauthenticated probe used to hand the machine's id and name, the swe version and the hub's uptime to the whole tailnet; it is a reachability check again. swe remote status now reads the machine row and version from the local machine's own files (it was the only consumer of those fields — the iOS client keeps an unused status() method, and swe remote setup only checks whether the route answers).

  • POST /v1/pair is rate-limited. Token exchanges get the same 5-per-10-minutes per-source-IP cap as /v1/pair/request, counted in a budget of their own and checked before the tailscale whois fork — a flood can't turn into subprocess churn.

  • The unauthenticated routes answer only Host names the hub serves. A plain loopback bind now records 127.0.0.1, localhost and [::1] (with the bound port) as its Host values — where previously the DNS-rebinding check had nothing to compare against — and a loopback bind behind tailscale serve keeps them alongside the public URL's name. A tailnet bind names every spelling of its own node — the bind value, the tailnet IP and the MagicDNS names — so the link swe remote pair writes passes whichever one it uses. /v1/status, /v1/pair, /v1/pair/request and the request poll refuse any other Host with 403 bad_origin, so a page that rebinds its domain to 127.0.0.1 can't drive the pairing surface.

  • iOS: the App Transport Security exception is scoped. The blanket NSAllowsArbitraryLoads is gone. *.ts.net (MagicDNS hub names) gets an insecure-HTTP exception, and NSAllowsLocalNetworking covers the unqualified or .local names and IP literals — including Tailscale CGNAT addresses — a hub address can take; arbitrary domains are back under full ATS.

  • An enabled-but-incomplete ntfy config no longer parks a dead subscriber on the hub bus. enabled without url/topic subscribed a queue nothing drained; it filled to the 2000-event cap and silently dropped events. The notifier now starts only when the config can actually post, and unsubscribes rather than leaving the queue behind.

  • ntfy approval actions carry a scoped token, not a device credential, and prompts are redacted. The Allow/Deny/Always buttons used to send Authorization: Bearer <cred> for the ntfy-actions device row — a full-power credential good for every attached session — through the ntfy topic, where the host (and ntfy.sh's relay for iOS delivery) could read it. Each notification now mints a token bound to (session, request_id): single-use, ten minutes, accepted only by the approval route, and retired the moment that request resolves — overlapping requests on the session keep their buttons. The prompt text also runs the transcript secret-redactor plus a length cap, so a Bearer sk-... inside a permission menu can't reach the topic either. Every hub start revokes the legacy ntfy-actions device row and scrubs it from notify.json — notifications disabled or half-configured can't strand it live — and a failed revoke keeps the fields to retry rather than losing the only handle on a leaked credential. Paired devices keep working on the approval route unchanged.

    • A transcript that shrank was always re-read from byte zero, so a copytruncate-style rotation (logrotate, an in-place rewrite that kept the head) replayed the whole transcript as new message.appended events.   • OpenCode 2.x sessions show up again. OpenCode 2.x writes new sessions only to session_v2 and their turns only to session_message, so every session made since the upgrade was missing from swe session, search, status, transcripts, the phone app and usage. swe and the Mac app now read both stores, each session and reply once.

  • swe session lists OpenCode sessions again. opencode 2.x turned its workspace table into provider bindings with no directory column, so the session query's workspace join failed with "no such column: w.directory" and every OpenCode row silently vanished. The query now checks workspace's columns first and joins it only as a path fallback when directory is there (older opencode, Kilo today).

  • Quiver opens the Sessions page faster. On a 2,450-session history a switch to Sessions held the main thread for about 155 ms; it now takes about 90 ms. The page used to filter every session several times per redraw and reread the ledger on every visit. It now keeps the filtered list, totals, day groups and filter choices until the sessions or filters change, and rereads usage only when the ledger changed.

  • Phone sends return immediately instead of hanging for the turn. POST /v1/sessions/{key}/message now answers 202 and runs the send on a per-session worker: queue mode waits for the session to go idle (up to 30 min) before injecting, steer writes at once, and the outcome lands as a command.result event carrying the caller's client_id. The PWA draws an optimistic bubble, keeps the composer visible (disabled) on observed sessions, and treats queued attaches as success. Attaching a claude session with no tmux on PATH now resolves to the headless channel instead of failing.

  • A board load no longer crashes the app on the GitHub pages. The Pages surface's persist closure — a literal formed on the main actor and handed to quiver.gh-history — inherited @MainActor isolation, and the runtime's queue assert trapped the moment the write queue called it. Repos with a Pages site hit it on their first board refresh. The persist parameters are @Sendable now, which keeps the closures nonisolated so the write queue can run them.

  • Resumed Codex threads are one session again. Every codex resume writes another rollout-<iso>-<thread>_<rollout>.jsonl, and the parser keyed each file on the trailing uuid — the resume's own rollout id, which the session index, the thread store and codex resume have never heard of. The thread uuid is the first one, so swe session now folds every resume into the thread's single row (the newest file stands for it), emits a resume hint codex resume can resolve, and finds the thread's real name. Index records written after the rollout's own timestamp no longer feed the rename check, and a resume that only re-states the live name can't stretch its rename window — resumes stopped reading as renames.

  • Quiver's main window goes fullscreen. A SwiftUI Window scene marks its NSWindow .fullScreenNone, so Enter Full Screen stayed off the green button's tiles and ⌃⌘F even though the window resized. The scene's content now opts in with .windowFullScreenBehavior(.enabled).

Their per-model usage read now runs on its own read-only ledger connection, off the main thread, instead of queueing behind a log scan (up to 3s on a busy ledger).   • A fresh Linux + Nix install bootstraps cleanly. Six first-run bugs together made a new machine look broken: any invocation — even a failed unknown command — created ~/.quiver/config/harness.json before it was asked for anything (a read now stays a read; save_registry is the one scaffolder), swe init skipped harnesses that had never run yet because a config dir was the only install evidence (a binary on PATH counts now, so Nix/uv installs like crush get their ~/.config/crush links, hooks included), swe doctor reported npm's global bin as the bare prefix when <prefix>/bin did not exist yet (the POSIX convention is the answer, unconditionally), swe list and swe check disagreed about the same registry because archived rows counted in one and vanished in the other (both now print the active count plus the shelved one, and an empty registry is a deliberate empty state instead of a header over 0/0), and swe discover --apply-all archived a home-scan find like hermes even when its binary probed a live version (the probe result, not the source, decides now; a find the confidence floor refuses is named with its remedy instead of silently dropped). 1.0.0 - 2026-10-13

First stable release. swe and the Quiver macOS app share one data model under ~/.quiver, every --json command uses the {schema, data} envelope, and the design is documented under docs/: data model, app architecture, backend architecture, JSON contracts and testing.

Highlights since 0.2.10: Cursor's Grok Bot allowance, harness display names and primary colours, Devin quota handling, and in the app: per-account menu bar and widget projections with live previews, Compute trends, plugin and skill editing, MCP Local/Remote groups, collapsed service status cards, API key checks and editing, a cached and source-isolated Overview, and four audits (databases and caches, app structure and contracts, swe controller / service / model layering, tests with an 84% coverage floor).

Added

  • Cursor's Grok Bot allowance shows with its other limits. Cursor gives Grok Bot its own weekly allowance, apart from the billing cycle. swe list --usage --json now lists it as a grok_bot window on Cursor (used percent, reset time, a week long), read with the same Cursor login from DashboardService/GetSandUsageStatus on api2.cursor.sh. It is never the headline figure, and a seat on a pooled enterprise allowance or with no included Grok Bot limit gets no window. The call is optional like the plan and hard-limit ones: a failure leaves the reading as it was. Those optional calls now get 3 seconds instead of 1.2, since Grok Bot's host needs a connection of its own. The macOS app labels the window "Grok Bot".

  • Harnesses get a display name, editable with swe edit --display-name. A harness is keyed by its registry name and launched by its command (cursor runs cursor-agent), which is no way to label it in the app. harness.json entries now take an optional display_name ("Cursor", "Qwen Code"); absent or empty means unset. swe edit <name|alias> --display-name="Qwen Code" sets it (whitespace is trimmed) and --display-name= clears it; --display_name= and --set=display_name=... work too, and the interactive editor lists it as "display name". swe list --json rows carry display_name next to name (null when unset), swe edit --json reports "display_name" in changes, and swe info shows it when set. Nothing else changes: the swe list table keeps its columns, and a harness without a display name prints exactly as before. Re-adding or reinstalling a harness (swe add, swe add -i, swe install) keeps the name you gave it.

Changed

  • The desktop widgets get their own sidebar page. "Menu bar and widgets" split in two: "Menu bar" keeps the status item and popup settings and previews, and a new "Widgets" page lists the four widget kinds with the same underline tabs, previews and per-widget settings. The stored tab settings keep working; a leftover "widgets" selection on the Menu bar page falls back to the first tab.

  • The discover and setup commands emit the standard JSON envelope. swe harness discover --json, swe mcp discover --json, swe skills discover --json and swe setup --json used to print bare json.dumps output. They now emit the same {schema: 1, data: ...} document as every other --json command: discovery rows live under data.findings, and the setup preview under data.harness / data.mcp / data.skills. An --apply run adds an applied object inside the same data, so a --json --apply invocation prints one document instead of two.

Fixed

  • swe list --usage --json served an hour-old limit reading instead of a fresh one. Piped output gave each provider's fetch a 2 second cap, and a fresh swe process (which is how the macOS app reads limits) often needs longer for its first Cursor or Devin request, so it fell back to the last cached reading, up to 24 hours old. The app then showed "Fetched 1h ago, couldn't refresh". --json now waits up to the same 25 seconds an interactive terminal gets; the piped table keeps the short cap.

  • swe skills --json listed a hub plugin's skills from Claude's stale cache. Claude Code runs a plugin from a directory marketplace (every one in ~/.quiver/plugins) straight from the marketplace's folder, so a skill added to the source loads at once while the copy under ~/.claude/plugins/cache keeps the skills it had at install time. The listing read that copy, so a new skill was missing from it and from the app's Skills page, and a deleted one lingered. Such a plugin's skills are now read from <marketplace folder>/<source path in marketplace.json>/skills, and its cached versions are skipped, so no skill appears twice. Plugins Claude fetched (github, git, a URL) still run from the cache and are listed from there.

  • A broken config file no longer corrupts --json output. When a --json command hit an unreadable config (a malformed harness.json, say), the error went to stdout, where the app expects only JSON. It now goes to stderr for every --json command; without --json nothing changes.

  • swe find plugins flagged Claude Code plugins as out of date when they weren't. Claude Code reads a directory-marketplace plugin straight from its folder, so the copy under ~/.claude/plugins/cache is a leftover it never loads, and claude plugin update reports nothing to update. Comparing against that copy raised "N files differ" findings no fix could clear. Claude is no longer checked for stale copies; Codex, which runs its own copy, still is.

  • swe find plugins kept calling a Codex plugin stale after its fix ran. Codex follows no symlink when it copies a plugin, so a source whose .codex-plugin, .cursor-plugin or .factory-plugin was a symlink never matched its copy, and codex plugin remove && add changed nothing. The source is now compared the way Codex copies it, without its symlinks. A symlinked .codex-plugin is reported as a new kind, linked-manifest: Codex skips it and installs a manifest it generates itself, with no version (the copy shows up as local). Its fix replaces the link with a real copy of its target (copied beside the link first, then swapped in, so a failed copy leaves the link and its finding), and the next run offers the reinstall. The app shows it as "Linked manifest".

  • swe skills unlink ~/.x/skills unlinked the wrong thing. A path to a linked harness root resolved to the shared tree it points at, so the command tried to unlink shared and refused. A symlink given by path is now the root it names. This bit every harness swe skills has no label for (claude-work, opencode, droid, hermes, …).

  • swe init no longer registers and links every app with a skills/ folder. A non-terminal run (a nix rebuild's activation script, say) used to register each unknown ~/.<name>/skills as a harness and link it to the shared tree, so a token usage tracker's cache folder and a browser's skills folder both ended up as "harnesses". Now a new folder is linked only once someone ticks it: a non-terminal run leaves it alone and reports it as skipped, a cancelled picker links nothing, and the picker pre-ticks only folders whose owner has a command on PATH or a catalog entry. Aside, Pinokio, TokenTracker and Ollama are named in NOT_HARNESSES and never offered or linked; an active registry entry under the same name still wins. --yes still takes everything.

  • swe harness discover --apply NAME… and --pick. Registering was all-or-nothing by confidence tier (--apply or --apply-all). Naming findings now registers just those, at any confidence, and --pick opens a multiselect in a terminal with only catalog matches ticked. The home scan skips the NOT_HARNESSES apps too.

  • Ollama is out of the harness catalog. It was listed "so discovery names it", but catalog matches are exactly what discover --apply registers, so a local model runtime kept landing in harness.json. It is now in the PATH scan's exclude list instead, and gone from the alias help.

  • Claude no longer cries re-login on a self-healing token. An expired access token beside a refreshToken is a live login — Claude Code refreshes transparently on its next call — so the fetcher now serves the last reading from claude's own ≤24h cache instead of the red re-login, and a re-login marker in the shared cache is re-derived on sight rather than replayed for the TTL. The label is kept only for an expired token with no refreshToken, the case that genuinely needs claude auth login. Cache ages are honest now too: each provider's reading carries its own updated_at, a re-served stale reading keeps its real fetch time, and freshness is judged per provider — so a persistent refetch on one provider (the re-derived re-login) can no longer rewrite the envelope and keep every other provider's cached value alive forever.

  • swe providers add no longer erases removal tombstones. add saved a registry loaded without the _removed bookkeeping list, silently dropping every recorded removal — previously-removed default providers all came back on the next load. add now preserves _removed, lifts only the re-added provider's own tombstone, seeds a re-added builtin's default fields instead of persisting a bare record, and resolves aliases to the canonical slug instead of forking a duplicate entry. On the codex side, split_codex_toml now folds stray [mcp_servers*] tables found later in config.toml into the region (TOML allows them anywhere) instead of writing them twice on save — an invalid duplicate-table file — and _toml_value/render_codex_server handle datetime/date/time values tomllib produces instead of crashing or silently dropping the key.

  • Every subcommand now answers --help. swe report followup --help, followup <action> --help, report followups --help, and report warnings --help used to error out ("Unknown follow-up action", a bogus usage line, or a manifest-suffix complaint) — or worse, followup add --help recorded a follow-up literally named "--help". swe providers remove --help reported a missing provider named "--help", swe session help and swe models help were rejected as unknown arguments, and swe providers --help printed the short summary whose last line pointed back at swe providers --help itself — it now reaches the providers group's own detailed help.

  • Untrusted strings can no longer drive the terminal. Session titles, transcript text, file previews, directory names, and MCP server names all originate outside quiver, and a crafted value carrying an OSC-8 hyperlink, an OSC-52 clipboard write, a cursor-moving CSI, or a bare BEL/CR previously printed verbatim — inside a table cell, a picker row, or a find preview it could paint itself, open a link, or rewrite rows. A new console.sanitize removes every escape class (OSC through BEL/ST/end-of-string, CSI including private modes, charset and two-byte escapes, lone ESC) and maps C0/C1 controls to spaces (sanitize_document keeps \n/\t for transcript text, turns \r into a newline, and deletes other controls so a byte inside a credential cannot split it before redaction). Applied at the render boundary: table text/path/list cells, _display_title, the agent column, picker preview sources and labels, the checklist and tri-state labels, find-browser labels/details/preview rows, tree and path printing in swe find, and MCP name/label display. strip_ansi widened to match the same escape classes so width math is right on hostile input, while preformatted cells remain an intentional trusted styling path. Transcript text is cleaned inside _clean_text, so reports and previews share the guarantee.

  • swe mcp sync preserves the target's own format keys on overwrite. Syncing over an existing entry dropped everything outside the canonical shape: an opencode server marked enabled: false was silently re-enabled, a droid type: sse became http, and claude's disabled/autoApprove vanished. Overwrites now merge the target's extension keys back over the emitted fields. Also in the MCP domain: redact() now swaps long (16+ char) credentials wherever they appear in a string, so a ?key=TOKEN URL resolved into a harness config redacts back to ${NAME} in the hub instead of persisting plaintext (resolve() always substituted mid-string; redact never did); server_summary redacts before printing so mcp sync's conflict display and mcp doctor no longer echo credential-bearing URLs; and an unverified registry name containing /, \, or .. gets no optimistic ~/.<name>/mcp.json path — mcp sync/list/status/diff/validate on it exit cleanly instead of a write outside the home directory or a KeyError/AttributeError crash.

  • Terminal widgets restore the terminal on every exit path. The session picker, checklist, tri-state picker, and find browser each hand-rolled raw mode and cleanup, so a fatal signal (or an exception between tty.setraw and restore) left the terminal raw with mouse tracking on. A shared keys.raw_terminal now owns setup, mouse-off, cursor-show, and termios restore, plus signal handlers for SIGHUP/INT/QUIT/TERM that clean up through the raw fd before re-raising. keys.read_key polls before each byte of an escape sequence so a truncated Esc [ can no longer block forever, and unknown sequences are ignored instead of cancelling the widget. Rows are padded by terminal cell width (console.cellpad), fixing misaligned columns under CJK text, combining marks, and wide emoji. swe session and friends also read CR, LF, and CRLF correctly from pipes now: a piped a\r\nb\r\n used to eat every second answer, and piped input no longer echoes back into the output.

  • Malformed config files can no longer be wiped by a write. swe mcp sync/discover --apply/edit treated an unparseable harness config as {} and then rewrote it holding only the MCP slice — for claude that meant ~/.claude.json's OAuth tokens, projects, and settings destroyed. load_json now raises CorruptConfigurationError on malformed or non-object content; read paths (mcp list/status/diff/discover, get_hub_servers) warn and degrade while every write path refuses. The same guard covers quiver's own files: harness.json and providers.json raise a clean error on a corrupt file instead of a raw traceback or a silent overwrite-with-defaults (the providers "corrupt reads as read-only" path was fake — the seed branch overwrote it), skill_catalogs.json refuses to save over a malformed file, and both registries plus the catalog file now write atomically via atomic_write_text so a crash mid-write can't leave a truncated file that bricks the next run. Non-object JSON ([1] as mcp.json) warns instead of crashing with AttributeError, and the top-level swe, swe mcp, and swe providers entry points all turn ConfigurationError into a red message + exit 1.

  • One malformed session record no longer poisons swe session. json.loads accepts NaN/Infinity literals and sqlite REAL columns can hold ±Inf — a cline meta file with "started_at": NaN killed the whole listing at int(diff / 86400). Session now coerces timestamp (non-finite or unparseable → 0.0), drops non-string path values to missing (a json number would otherwise survive as a relative path a --here filter could match), and stringifies agent/title/session_id/tool_name at construction, so every engine and the session-cache reader share the guarantee. parse_iso_ts rejects non-finite inputs too, and absurd --days=/--end= values (--days=1000000, --end 9999-12-31) now hit the same clean error path as other bad dates instead of an uncaught OverflowError.

All tables are rebuilt: nested flag sets (swe mcp sync --<TAB>, swe skills move --<TAB>, swe report followups --<TAB>), second-level subcommands for mcp/find/skills/providers/session, third-level actions (report followup, skills catalog, config setup), tool names for mcp sync/diff (excluding ones already typed, aliases included), provider names for providers info/remove, and server names for mcp edit <tool>. swe doctor now checks the completion tables against dispatch so the drift cannot silently regrow.

  • Audit leftovers: hidden flag, dead flag, 404 help topics, inconsistent exits. swe mcp sync --prune worked but was missing from swe mcp sync help; it is documented now. swe skills help tree/scope/scopes 404'd on topics swe help skills advertises — they now print a help page explaining the swe find skills -r hand-off. --json on swe skills link/unlink/move was parsed and ignored; it now prints a machine-readable result, and the shared parser rejects flags that do not belong to the subcommand (--mkdir on link/move, --force on unlink, any unknown flag). swe report daily --help and bare swe report/swe report help print the report help and exit 0 instead of erroring, matching mcp/providers/skills/config. swe session use abc/use say "Usage: swe session use " instead of "Unknown argument". swe mcp ls now aliases mcp list. Leftover argv that used to be silently absorbed is rejected: a --flag typo in swe list no longer filters the listing on the typo'd word (-x and --x both fail "Unknown flag"), swe models/skills/providers list reject unknown flags, and trailing positionals are an "Unexpected args" error on find, info, remove, star, list, providers, autocomplete, and the no-arg commands (check, tags, aliases, doctor, list edit, list legend, harness edit).
